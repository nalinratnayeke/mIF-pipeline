# InstanSeg training matrix

`instanseg_experiments.json` is the reviewed source of truth for long InstanSeg training runs. The submission wrapper is plan-only unless `--submit` is supplied.

`instanseg_experiments_multihead.json` is the replacement matrix using the released fluorescence model's two-decoder architecture. It sets `multihead: true` in shared defaults and gives every output a distinct `_multihead` name. The original matrix is retained as the provenance record for the shared-decoder experiments submitted on 2026-08-24.

## Initial experiment design

The ready CPDMI experiments are:

1. `cpdmi_050_t256_w128_heavy`: a 0.5-µm retraining control for comparison with the original operating resolution
2. `cpdmi_0325_t256_w128_heavy`: the primary 0.325-µm baseline
3. `cpdmi_0325_t384_w128_heavy`: a larger-tile test that isolates crop field of view while retaining the established instance and validation window

The initial matrix retains a 128-pixel instance window. At 0.325 µm/pixel this spans 41.6 µm, already comfortably larger than an ordinary nucleus and usually a whole-cell diameter. Increasing it would also couple the experiment to validation postprocessing. The geometry comparison therefore changes only the tile size from 256 to 384 pixels, testing physical context without changing the loss window.

The fork's custom channel-drop smoke test passed, so two mixed CPDMI+TissueNet experiments are ready. Both use heavy augmentation with CPDMI 0.3 / TissueNet 0.05 suppression; they compare 256- and 384-pixel tiles while retaining the 128-pixel window. The lower TissueNet probability keeps both channels in approximately 90.25% of ordinary two-channel samples before optional noisy-channel augmentation, while retaining some missing-channel robustness. Minimal-augmentation mixed arms were removed because they would confound the effect of adding TissueNet with a substantial departure from the established heavy training preset.

The mixed runs use dataset weighting so CPDMI and TissueNet each contribute approximately half of sampled records despite their unequal dataset sizes. Their `length_of_epoch` is 6,000 rather than 3,000: the expected contribution is therefore approximately 3,000 CPDMI and 3,000 TissueNet samples per epoch. This preserves CPDMI exposure per epoch relative to a CPDMI-only run while deliberately adding an equal amount of TissueNet exposure. At batch size three this is approximately 2,000 optimizer updates per mixed epoch, so each is intentionally about twice as long per epoch and does not have an update-matched training budget.

An augmentation parity audit compared every default preset generated by the fork with the reference snapshot. With `dataset_channel_drop_probabilities` omitted, all preset dictionaries were identical, including heavy fluorescence suppression at 0.3. The new mapping only replaces the amount passed to the existing final training-time `channel_suppress` step. Validation configuration is unchanged.

## Why batch size is fixed at three

Batch size is not treated as a free H200-throughput setting. The model uses batch normalization, batch size changes gradient noise, and `length_of_epoch` counts samples rather than optimizer updates. At 3,000 samples per epoch, batch 3 produces approximately 1,000 updates, while batch 6 would produce approximately 500. Increasing both batch size and epoch length would change total data exposure. The first matrix therefore keeps batch 3 to match the reported training schedule. A batch-size experiment is lower priority than a second random-seed run of the best configuration.

## Resources and source snapshots

The submission defaults are one generic GPU, 24 CPUs, 128 GiB RAM, and the seven-day `gpu` partition limit. This allows the scheduler to assign any compatible available accelerator rather than requiring an H200. Eight workers are passed to each InstanSeg loader. The additional CPUs leave room for the main process and for persistent training and validation workers.

The runner logs the assigned GPU and CUDA memory information. It does not automatically lower batch size on a smaller GPU, because doing so would change optimizer-update counts and training dynamics. The 256-pixel, batch-three smoke test used under 6 GiB reserved memory on an H200. A 384-pixel tile has 2.25 times as many pixels; it should remain practical on common 40–48 GiB cluster GPUs, but an actual out-of-memory failure should be handled as an explicit experiment revision rather than a silent fallback.

The `instanseg_training` environment uses an editable installation of the InstanSeg fork for interactive work and direct commands. All submitted jobs additionally use an immutable snapshot of that fork so every model is trained from the same source tree. On actual submission, the wrapper snapshots the complete fork working tree, including uncommitted channel-drop changes, under the batch directory. It also records the Git commit, status, worktree patch, matrix, and job runner. Queued jobs therefore cannot silently change when the development checkout changes.

Batch artifacts are written under:

```text
/data1/lowes/ratnayn/Data/instanseg/slurm_runs/<batch-name>/
```

Model outputs are written under:

```text
/data1/lowes/ratnayn/Data/instanseg/models/<experiment-name>/
```

The runner refuses to reuse an existing experiment directory by default.

## Wall-time and restart behavior

The fork writes three checkpoint files with distinct roles:

- `latest_checkpoint.pth` is atomically replaced after every completed epoch and is the restart source.
- `best_model_weights.pth` changes only when validation F1 improves and is the explicitly named model-selection artifact.
- `model_weights.pth` mirrors the best checkpoint for compatibility with the upstream model loader.

The latest checkpoint stores the model, optimizer, optional scheduler, hot-start/main phase, phase-local completed epoch, best F1, phase metric histories, training configuration, and Python/NumPy/PyTorch/CUDA random states. Resume validates the scientific configuration, restores the saved state, skips completed hot-start or main epochs, and continues until the configured total epoch count. A termination during an epoch still loses that incomplete epoch. Persistent data-loader worker random streams cannot be reproduced bit-for-bit after process replacement, although the parent random states are restored.

Fresh jobs refuse an existing model directory. Resume is explicit, accepts exactly one selected experiment, requires `latest_checkpoint.pth`, and refuses a directory marked by `training_complete.json`. Use a new SLURM batch name for the resumed allocation. For the most faithful source provenance, point `--fork-root` at the original batch snapshot:

```bash
scripts/submit_instanseg_training_matrix.sh \
  --batch-name instanseg_0325_resume1 \
  --experiment cpdmi_0325_t256_w128_heavy \
  --fork-root /data1/lowes/ratnayn/Data/instanseg/slurm_runs/instanseg_0325_20260824/source/instanseg \
  --resume

# After reviewing the plan:
scripts/submit_instanseg_training_matrix.sh \
  --batch-name instanseg_0325_resume1 \
  --experiment cpdmi_0325_t256_w128_heavy \
  --fork-root /data1/lowes/ratnayn/Data/instanseg/slurm_runs/instanseg_0325_20260824/source/instanseg \
  --resume \
  --submit
```

After reviewing the resolved commands, submit them with a five-day wall time:

```bash
scripts/submit_instanseg_training_matrix.sh \
  --matrix training/instanseg_experiments_multihead.json \
  --batch-name instanseg_multihead_0325 \
  --time 5-00:00:00 \
  --submit
```

To accept either an H100 or an H200 while excluding lower-tier GPU models, use
a generic GPU request together with the cluster's node-feature OR constraint:

```bash
scripts/submit_instanseg_training_matrix.sh \
  --matrix training/instanseg_experiments_multihead.json \
  --batch-name instanseg_multihead_h100_or_h200 \
  --gpus 1 \
  --constraint 'h100|h200' \
  --time 5-00:00:00
```

Review the plan and add `--submit` to submit it. A typed `--gres` request remains
appropriate when one exact GPU model is required; `--gres` replaces `--gpus`,
while `--constraint` is passed independently to Slurm.

```bash
scripts/submit_instanseg_training_matrix.sh \
```

```bash
scripts/submit_instanseg_training_matrix.sh \
  --batch-name selected_models \
```

Experiments should be enabled or disabled by editing `ready` in the matrix so the decision is preserved in Git. The wrapper intentionally provides no command-line bypass for a blocked experiment.

## Comparison strategy

Training-time validation scores are not sufficient for comparing CPDMI-only and mixed models because they use different validation compositions. Finished candidates should be evaluated with identical postprocessing on separate common holdouts:

- CPDMI validation
- TissueNet validation
- representative in-house multiplex fields

Postprocessing should be tuned after training rather than multiplied into the training matrix. At 0.325 µm/pixel, candidate peak-distance and minimum-area values near six and 24 pixels can be compared with the original 4/10 settings. The candidate window remains 128 pixels initially because its 41.6-µm physical span is already ample.
